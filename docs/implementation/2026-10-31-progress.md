## 適用順と未完了の区別

1. 個別PRの未完了要件と検証結果を確認する。PRが存在することと、全共通仕様を満たすことは別。
2. 新しいスコア受領RPCを使うPRは、先に実験場PRの[DB適用・読戻し・rollback手順](../chameleonjp-lab/18_common_score_receipts.md)を実施する必要がある。本番未適用のまま依存ゲームをマージしない。旧RPCへの自動フォールバックは二重送信を起こすため行わない。
3. GitHub Pagesが旧ブランチ配信のリポジトリは、Settings → Pages → Build and deployment → SourceをGitHub Actionsへ変更する。管理設定のAPIは403となる接続があり、この設定変更は未実施。各ゲームのPRに対象と設定値を記録している。保護・承認は解除しない。
4. 利用者が公開ブランチへマージした後、そのSHAのCI・build・配備成功と実際の公開URLを確認する。現時点でマージ後の公開成功は確認していない。
5. Codebergからの移行は、同一ゲームのGitHub版が実際に遊べることを確認してから、実験場のDB URL・共有文と旧ページの案内を切り替える。新URL未確認での強制転送は禁止。別originの名前・言語・音量・自己ベストは自動共有できないので、各PRの制約と移行案を確認する。

## 維持と検証の限界

- 既存のゲーム/モードslug、点数の符号・大小・精度、制限時間、終了条件を維持。公開登録と匿名開始集計を分け、名前なしでもゲーム・結果・ランキング・共有を使えるよう各ゲームを改修中。
- 旧DBは normalized_name で集約するため、同名別人の分離と改名後の本人継続は未解決。新しい受領UUIDはプレイの重複防止用で、参加者IDの問題を解決したものではない。既存記録を名前だけで新IDへ帰属させない。
- ローカル自動試験・Chromium/WebKitと、iPhone17 ProのSafari実機確認を区別する。実機・母語話者による翻訳自然さ・実音の試聴は未実施。各PRに短い実機確認手順を記載。
- 本番ランキングに検証用スコアは登録していない。DBテストは合成データのPostgreSQL、ブラウザ試験は原則模擬RPC。実際の公開ページを読んだ確認は、そのURLと確認内容を個別記録する。
- rollbackはコードをrevertするPRで行う。スコア・参加者・設定・未送信キュー・受領証拠を削除しない。既存の保存キーを一括削除してキャッシュを更新する方法は使わない。
