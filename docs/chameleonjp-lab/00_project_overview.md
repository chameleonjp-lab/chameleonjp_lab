# カメレオンJP 実験場・ランキング連携 全体仕様

最終更新: 2026-06-12
対象: カメレオンJPの実験場 / 詳細ランキング / Supabaseランキング連携

## 1. この文書の目的

この文書は、Claude CodeがカメレオンJPの実験場まわりを修正する前に、全体像を間違えずに把握するための入口です。

ここでいう実験場まわりとは、次の4つです。

1. 実験場トップ `index.html`
2. 詳細ランキング `ranking.html`
3. Supabaseのランキング取得・集計・スコア送信
4. 各ゲームの `index.html` に入れるランキング送信用コード

## 2. プロジェクトの基本形

カメレオンJPでは、スマホで遊べる小さなブラウザゲームをCodeberg Pagesで公開し、それらを「カメレオンJPの実験場」にまとめる。

基本構成は次の通り。

| 項目 | 仕様 |
|---|---|
| 公開先 | Codeberg Pages |
| ゲーム本体 | 原則 `index.html` 1ファイル |
| 使用技術 | HTML / CSS / JavaScript |
| ランキング保存 | Supabase |
| 実験場トップ | ゲーム一覧、集計、ランキング上位、導線を表示 |
| 詳細ランキング | 1ゲームごとの初回ランキング・ベストランキングを表示 |
| 仕様共有 | GitHubのこのリポジトリをClaude Code向けに使う |

## 3. 正とするデータ

最新方針では、実験場に表示するゲーム情報の正はSupabase `public.games` である。

古い実装では、`index.html` や `ranking.html` の中に `GAMES` という固定配列を持っていた時期がある。既存コードに固定配列が残っていても、それだけを正にしてはいけない。

新規改修では、次の優先順位で扱う。

1. `public.games` の `is_active = true` を正とする。
2. `display_order` で表示順を決める。
3. 固定配列が残っている場合は、通信失敗時のフォールバックか、旧実装として扱う。
4. 固定配列しか見ていないコードは、Supabase中心に直す候補とする。

## 4. Supabaseの公開設定

ブラウザ側で使う値は次の通り。

```js
const SUPABASE_URL = "https://mlpnjgezrnhdxsxolyzj.supabase.co";
const SUPABASE_PUBLISHABLE_KEY = "sb_publishable_drzcy0v97knU6FgjqSgBHw_0A9XPdFM";
```

このPublishable keyは公開HTMLに入れてよい前提で共有されている。ただし、`service_role` キーは絶対に公開HTMLへ入れてはいけない。

## 5. Supabaseで使う主なもの

| 用途 | 名前 |
|---|---|
| ゲーム一覧・表示設定 | `public.games` |
| スコア保存 | `public.game_scores` |
| スコア送信 | `submit_score` |
| 初回ランキング取得 | `get_first_try_ranking` |
| ベストランキング取得 | `get_best_score_ranking` |
| プレイ回数・参加人数取得 | `get_game_play_stats` |

重要: `public.scores` ではなく `public.game_scores` を使う。

## 6. `public.games` に必要な主な列

`public.games` は、実験場トップと詳細ランキングが読む前提のゲーム台帳である。

必要な主な列は次の通り。

| 列 | 役割 |
|---|---|
| `game_slug` | ゲームを識別する英数字ID |
| `title` | 表示名 |
| `game_url` | ゲーム本体の公開URL |
| `description` | 実験場カードに出す説明 |
| `share_text` | シェア文。なければタイトルと説明から作る |
| `is_active` | 実験場に表示するか |
| `display_order` | 表示順 |
| `top_ranking_type` | トップで出すランキング。`first` または `best` |
| `score_order` | 大きいほど良いなら `desc`、小さいほど良いなら `asc` |
| `score_unit` | `点`、`秒`、`%` など |
| `score_scale` | 内部整数から表示値へ変換する倍率 |
| `score_decimals` | 表示小数桁 |
| `score_label` | 通常スコアの表示名 |
| `first_score_label` | 初回ランキング用の表示名 |
| `best_score_label` | ベストランキング用の表示名 |
| `release_date` | 公開日 |

## 7. ランキングの考え方

このプロジェクトでは、ランキングは2種類ある。

ひとつは、初回記録。プレイヤーがそのゲームで最初に登録した記録を使う。もうひとつは、ベスト記録。同じプレイヤーが何度遊んでも、その人の一番良い記録を使う。

スコアが大きいほど良いゲームは `score_order = 'desc'`。タイムや誤差のように小さいほど良いゲームは `score_order = 'asc'` にする。

同率順位は、Supabase側のRPCが `rank_no` を返すことで扱う。フロントは `rank_no` をそのまま表示する。これにより、同点の場合は `1位, 1位, 3位` のように表示できる。

## 8. ゲーム側の必須仕様

各ゲームの `index.html` には、ランキング対応として次を必ず入れる。

- プレイヤー名の必須入力
- 名前のブラウザ内保存
- ゲーム終了時の自動送信
- 送信中・送信済みフラグによる二重送信防止
- 送信成功・失敗の表示
- 結果シェア
- 実験場へ戻る導線

結果画面に「ランキング登録」ボタンを置き、プレイヤーが押した時だけ送信する作りにしてはいけない。ゲーム終了時に自動送信する。

## 9. スマホ向け共通仕様

カメレオンJPのゲームは、スマホで遊ぶことを前提にする。特にiPhone SE級の横幅でも操作できるようにする。

必ず守ること。

- 横スクロールを出さない。
- ピンチズームを抑える。
- ダブルタップ拡大を抑える。
- 長押しコピーをゲーム操作の邪魔にしない。
- ボタンは指で押しやすくする。
- 結果画面やモーダルが画面外にはみ出さないようにする。
- ゲーム中の通常操作をブラウザジェスチャーに奪われないようにする。

## 10. 新規ゲーム追加の大まかな流れ

新しいゲームを追加する時は、次の順で進める。

1. ゲーム本体をCodeberg Pagesで公開する。
2. ゲーム側 `index.html` にSupabaseスコア自動送信を入れる。
3. Supabase `public.games` にゲーム情報を登録する。
4. `submit_score` で送信できることを確認する。
5. `get_game_play_stats` で集計が出ることを確認する。
6. `get_first_try_ranking` と `get_best_score_ranking` で順位が出ることを確認する。
7. 実験場トップにカードが出ることを確認する。
8. 詳細ランキング `ranking.html?game=game_slug` が開けることを確認する。

## 11. 現在の注意点

過去の不具合として、次のような失敗が起きている。

- `public.scores` という存在しないテーブルを読みに行った。
- `created_at` という存在しない列で並べようとした。
- Publishable keyを入れたのに、RESTフォールバック側でBearerを付け忘れた。
- 実験場トップと詳細ランキングのゲーム一覧がずれた。
- 結果画面で任意送信ボタンが出て、共通仕様から外れた。

同じ失敗をしないため、作業前にこのリポジトリの仕様を必ず読むこと。
