# 名前に関係なくプレイ開始を記録する

通常プレイが始まるたびに1回記録します。名前なしで始めたプレイや途中で終了したプレイも含みます。続きからの再開、練習、開始前の取り消し、結果の送信や再送は加算しません。ゲームによって専用の開始処理があり、すでに名前ありと名前なしを記録している場合はその処理を使います。

## 共通処理

ゲームは通常プレイを実際に開始する箇所で、`play-start.js` の `recordPlayStart(gameSlug)` を1回呼びます。難易度別にランキングがある場合は、その難易度で使う登録済みのIDを渡します。開始ごとに異なるIDを発行し、同じ開始の再送では同じIDを使います。通信はプレイを待たせません。名前やスコアはこの処理から送信しません。保存領域を使える場合は未送信の開始を短期間保存します。

## 公開と集計の切り替え

1. [SQL](sql/lab-counted-starts-v1.sql)を既存の実験場データベースに適用し、共通のスクリプトを公開します。初期状態ではゲームごとの集計は従来どおりです。
2. 開始処理を呼ぶゲームを公開します。対象ゲームとモードを照合し、試験用の応答で名前あり・なしの双方が開始で1回送信することを確かめます。
3. 確認したモードだけをデータベース所有者の権限で `select private.enable_lab_counted_starts_v1('game_slug');` により有効にします。公開のゲーム一覧に存在することを確認してから有効になります。有効化を繰り返しても、旧集計の値を取り直しません。
4. 有効化時点の旧プレイ総数に、その後の新しい開始を加えます。保存済みの名前付き成績とプレイ人数は従来の情報を読み取ります。旧ブラウザーが切り替え後に送った結果は順位表へ反映できますが、開始の情報がないため新しい計測の総数には入れません。切り替え前に数えられなかったプレイも遡って加算できません。

本番には試験スコアを送らず、SQLと通信の確認は分離した試験環境で行います。切り戻す必要がある場合は、切り替え前の `get_game_play_stats` 定義へ戻せます。記録した開始IDは保持し、旧表示に戻している間の新しい計測の扱いを確認してから再開します。
