# ブラウザゲーム共通仕様（2026-10-31）

この文書は2026-10-31の依頼を今後の制作にも適用するための規約。実装完了の宣言ではない。既存文書の「名前必須」等と競合する場合は本書を優先する。ゲーム別対応表には **既存で対応済み／今回実装した／対象外（根拠必須）／未確認・未完了** を記載する。

## 対象と保存

現在の実験場表示・表示に使う登録情報・公開ページの3点を照合する。固定の予備データや古い文書だけでは対象としない。状態を取得できなければ対象判定未確認。未登録・未公開を今回のために登録・有効化・公開しない。

正式名、公開URL、リポジトリと基点SHA、関連PR、ゲーム/モードID、保存先、参加者キー、採点とランキング規則、言語・名前・音・端末保存キー、ビルドと公開設定を記録する。既存スコア・自己ベスト・参加者・IDは初期化せず、採点、精度、制限時間、難易度、不正除外は維持する。無料の既存基盤を優先する。

## 正式URL

同一ゲームの既存GitHub版がある場合、機能が揃い古い版でないことと実際の遊べるURLを確認し、GitHubの公開ページを正式URLにする。リポジトリ画面や推測URLを使わない。

初回配信が必要なら本体PR→利用者のマージ→公開・動作確認→実験場/旧ページ導線変更の順。新URL確認前の強制転送やDBリンク更新は禁止。GitHub版がなければ新リポジトリを作らず現在の公開先を維持する。

canonical/OG/ホーム共有/結果共有/関連リンク/DB game_url・share_textを一致させる。DB更新には対象条件・適用SQL・読戻し・rollbackを用意する。スコアIDはURLに合わせて変えない。異なるoriginのlocalStorageは自動共有されないため、サーバー記録、本人識別、端末設定を別々に検証する。未検証の全引継ぎ保証は禁止。

最低15 ID: `ja, en, es, pt-BR, zh-Hans, fr, de, ko, ru, it, zh-Hant, id, tr, vi, th`。追加言語を削除しない。

ホーム・説明・操作・問題・ゲーム中・結果・ランキング・設定・名前説明・通信中/空/失敗・X本文を翻訳する。選択肢だけの追加や英語fallbackを翻訳済みに数えない。保存設定→対応ブラウザ言語→英語の順を基本にし、既存設定と地域別の表示形式を区別する。

日本語のボタンは「Xでシェア」「ランキング」。名前や内部IDは翻訳しない。日本語固有問題は判断の目的を維持して各言語の問題を設計する。正解条件・選択肢数・問数・時間・配点を保ち、難易度同等性は別に検証する。切替で再抽選・時間復元・スコア消失・二重送信を起こさない。安全に切替できない問題言語は次のプレイへ適用する。

## 任意の名前と公開条件

ホームに編集・消去可能な名前欄と「名前を入力すると、名前と記録がランキングに公開されます。空欄でも遊べます。」の意味の短い説明を置く。

名前なしでもプレイ・結果・ランキング閲覧・共有を利用できる。開始時の有効名・公開参加可否・参加者情報をプレイへ固定し、その確定結果を自動送信する。空白だけは不参加。後からの入力で過去の匿名結果を公開しない。匿名開始統計は公開参加と区別して維持する。

名前変更・消去は次回から適用し、過去スコア削除や別参加者生成の理由にしない。同名の別人を統合しない。既存入力上限を確認して多言語名を安全なテキストとして表示する。IME確定だけで開始しない。

再表示・言語変更・再読込・再送でも同一プレイは1回だけ登録する。サーバーの冪等契約が必要であり、メモリ内フラグだけでは不十分。送信中/成功/失敗を区別し、失敗しても今回の結果を保持する。通信をプレイ開始/結果表示の必須条件にしない。既存の確定条件や不正判定を迂回しない。

**現行基盤の未解決事項:** players/game_scoresはnormalized_nameで本人を識別する。上記の改名継続・同名別人は現行APIだけで実現できない。旧記録を保持し、信頼できる本人確認がない記録を名前だけで新IDへ帰属させない。DB移行方式決定・実装・互換性検証が完了するまで、この要件を対応済みとしない。

## ランキング

ホームと結果のリンクは実際のカードが使う詳細URL。モードの送信slugと詳細slugを混同しない。結果でゲストを含め最大30参加者を表示する。30プレイを取得して名前を間引く方式は禁止。集計/期間/モード/点数/不正除外/同順位を実験場詳細と合わせる。suiteki_catchのfirstなど既存規則をbestへ統一しない。

保存先側で集計・制限し、同点順位は変えず表示境界だけ安定化する。読み込み/空/失敗/再試行を持ち、送信成功後の取得を古い応答で上書きしない。30件から圏外順位や全人数を推測しない。採点がないゲームに独自ルールを作らない。

## X共有

ホーム/結果に黒背景・白文字・長文が切れないボタン。ホーム本文はゲーム名・短い特徴・正式URL、結果本文はゲーム名・今回の確定値・必要な単位/モード・正式URL。表示言語で作り、自己ベストと混同しない。名前/内部ID/未確定順位/推測人数/過剰な称賛を含めない。

URLSearchParams等で本文・記号・改行・URLをエンコードしてXの投稿画面を開き、確定は利用者が行う。自動投稿・開いただけで投稿完了表示は禁止。キャンセルして戻っても結果保持。開けなければ本文とURLのコピー、コピーも失敗したら手動選択できる本文を用意する。

## 音

実在するイベントだけを対象に、イベント/役割/条件/重複抑制/実装箇所の表を作る。必要と判断したものは全て実装する。既存の雰囲気を維持し、既存/利用可能素材かブラウザ合成音を使う。

有効な保存がない初回はオン・0より大きい控えめ音量。保存済みfalse/0は有効。再挑戦/ホーム/言語/復帰で初期化しない。見つけやすいオンオフと音量設定を置く。利用者操作でAudioContext初期化/再開を試み、失敗してもゲームを進める。最初の操作がミュートなら先に反映する。

連打や連続得点は再生数/優先順位を制御。停止と後片付けを行い、非表示中の音を復帰後にまとめて鳴らさない。ミュートでも必要情報を伝え、音だけで答えが分からないようにする。実際の試聴はコード確認と別に記録する。

## 文言・画面

説明の重複と表記揺れを直し、数値・成功/失敗・操作・世界観・意図した曖昧さを保つ。表示文字列を処理の条件にしない。ホームの入力/開始/遊び方、結果の共有/再戦/ランキングを見つけやすくし、長い名前・翻訳・30名一覧でも操作できるようにする。

iPhone 17 Pro Safariを優先し、縦横・短い高さ・操作バー・safe-area・キーボード・IMEを考慮。PC操作も維持。全体作り直しやルール変更へ広げない。

## 配備・検証・報告

PRでは検証のみ。公開用ブランチのマージ後、そのSHAを検証・ビルドし成功成果物だけを配備する。古い実行/二重配備を防ぐ。PagesのSource、権限、environment、出力先を実際に確認する。秘密や開発ファイルを配信せず、設定/自己ベストの一括消去でキャッシュ問題を解決しない。保護や承認を解除しない。

各PRに対応表、対象根拠、保存契約、音一覧、文言理由、検証結果、マージ順、設定、DB適用/読戻し/rollback、残作業を添える。本番へ試験スコアを大量投入しない。実機がなければ、幅変更やWebKit試験と区別して実機手順を残す。翻訳自然さ・試聴・公開確認の未実施を実施済みにしない。

報告状態は「実装・PR検証済み」「利用者のマージ待ち」「設定や権限が必要」「本番公開後の確認待ち」を分ける。公開確認済みならURLと確認した変更を示す。
