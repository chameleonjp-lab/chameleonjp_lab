# ゲーム別ランキング注意事項・詳細版

最終更新: 2026-06-21
対象: カメレオンJPの実験場に登録している各ゲーム

## 1. この文書の役割

この文書は、`08_game_ranking_cautions.md` よりさらに細かく、ゲームごとのランキング制作で壊れやすい点をまとめる。

`08_game_ranking_cautions.md` は共通ルールと主要注意点を扱う。こちらは、実装時にCodexやClaude Codeが見落としやすい「ゲーム固有の例外」を扱う。

確定している内容は、過去のチャット履歴、Supabase `public.games` の最新一覧、現行の実験場仕様に基づく。過去履歴から明確に確認できない注意点は、無理に断定しない。

## 2. 全ゲーム共通で再確認すること

ランキングの基本は次である。

| 項目 | 原則 |
|---|---|
| 送信タイミング | ゲーム終了時に自動送信 |
| 任意送信ボタン | 原則置かない |
| 二重送信 | 送信中・送信済みフラグで防ぐ |
| 順位 | RPCの `rank_no` を使う |
| 初回ランキング | `get_first_try_ranking` と `first_score` |
| ベストランキング | `get_best_score_ranking` と `best_score` |
| 保存先 | `public.game_scores` |
| ゲーム台帳 | `public.games` |
| 公開HTMLのキー | Publishable keyのみ |

実験場トップでは、特に指定がなければベストランキングを出す。点数や階数は大きいほど良く、タイム・誤差・ゲーム数は小さいほど良い。

## 3. ゲーム別の注意事項

### 1. 虎に優しく / `torani_yasashiku`

このゲームは、初期からある点数ゲームとして扱う。

ランキング制作時は、基本形から外さないことが重要である。`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0` を使う。実験場トップでは、特に指定がないためベストランキング、つまり `最高スコア` を表示する。

注意点は、古いゲームなので固定配列や旧ランキング関数に残骸がある可能性を見ること。`public.scores` や古い関数名に戻してはいけない。

### 2. 暇つぶし / `nayuta_no_himatsubushi`

点数ゲームとして扱う。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0` を維持する。実験場トップでは `最高スコア` を出す。

注意点は、ゲーム名が短く一般語に近いため、固定配列やSQLで別名を作らないこと。`game_slug` は必ず `nayuta_no_himatsubushi` にそろえる。

### 3. イロアテ / `iroate`

このゲームはタイム系である。点数ゲームではない。

`score_order=asc` なので、小さい数値ほど上位になる。`score_unit=秒`、`score_scale=100`、`score_decimals=2` を使う。保存する値は、表示秒数を100倍した整数である。

たとえば、34.15秒なら `3415` を送る。`34.15` を小数のまま送ったり、`34` に丸めて送ったりしない。

実験場トップでは `ベストタイム` を出す。`最高スコア` と表示すると誤解が出る。

### 4. 夢を見たんだけどさ / `yume_wo_mitandakedosa`

点数ゲームとして扱う。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高スコア` を出す。

注意点は、60秒の生存・回収系であっても、ランキングは時間ではなく点数で競うこと。生存時間をランキング値に混ぜない。

### 5. 水滴キャッチ / `suiteki_catch`

このゲームは、実験場トップで初回ランキングを出す例外である。

`top_ranking_type=first` を使う。実験場トップでは `初回スコア` を表示し、`get_first_try_ranking` の `first_score` を使う。

詳細ランキングでは、初回と最高スコアの両方を出す。

過去の実装では、結果状態として `clear`、`retire`、`fail` を分ける流れがある。ランキング送信対象にする結果と、ローカル保存だけにする結果を混ぜない。初回ランキングを代表にする理由があるゲームなので、勝手にトップをベストへ戻してはいけない。

### 6. 上手に描けるかな？ / `jouzuni_kakerukana`

達成度・点数系として扱う。

現在のSupabase一覧では `score_unit=pt` である。過去の文脈では `%` と扱われた時期があるため、古い表示を残さない。

`score_order=desc`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高スコア` を出す。

注意点は、単位を勝手に `%` に戻さないこと。`public.games` の現行値を正にする。

### 7. 充電ｶﾞｯ / `juden_ga`

点数ゲームとして扱う。

過去の実装では、スコア計算に `勝ち数×100 - 負け数×40 - BUMP回数×15` のような計算が使われていた。ランキング側では、ゲーム本体が確定した最終スコアをそのまま送る。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高スコア` を出す。

注意点は、勝敗数やBUMP回数を個別にランキング値へ送らないこと。送るのは最終スコアである。

### 8. あなたの1秒って / `anatano_1byou`

このゲームは誤差が小さいほど良い。

`score_order=asc`、`score_unit=秒`、`score_scale=100`、`score_decimals=2`。実験場トップでは `ベスト誤差` を出す。

過去に `anatano_1byo` のような誤slugが出たことがある。必ず `anatano_1byou` に統一する。

注意点は、合計誤差を競うため、小さいほど上位であること。`desc` にするとランキングが逆になる。

### 9. ベク取る / `bekutoru`

クリアタイムを競うゲームである。

`score_order=asc`、`score_unit=秒`、`score_scale=1000`、`score_decimals=3`。ミリ秒をそのまま整数として送る。

たとえば、1.234秒なら `1234` を送る。`1.234` をそのまま送らない。

過去に、結果画面で任意のランキング登録ボタンになっていたことが問題になった。終了時に自動送信する。他のゲームと同じ共通ランキング仕様に合わせる。

### 10. 尊厳を賭けようか / `songen_wo_kakeyouka`

点数ゲームである。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高スコア` を出す。

このゲームは、勝利、敗北、引き分け、リタイアなどの結果表示が重要である。リタイアを送信対象にする場合は、他ゲームと同じく結果画面を出してから自動送信し、二重送信を防ぐ。

注意点は、勝敗結果の文言やシェア文を直す作業と、ランキング送信ロジックを混ぜて壊さないこと。オンライン対戦準備やローカル2人対戦の修正時も、CPU戦ランキングを消してはいけない。

### 11. ヒトを許すな！ / `hito_wo_yurusuna`

点数ゲームである。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高スコア` を出す。

このゲームは、タワーディフェンス型で波数の意味が強い。ランキング表示で点数だけだと、到達波数やクリア状況の意味が足りない可能性がある。

注意点は、スコア順位を点で決める場合でも、必要に応じて到達波数やクリア波数を補助表示すること。ただし、補助表示をランキング値そのものと混ぜない。

### 12. 負けたらお前のせいだから / `maketara_omae_no_sei_dakara`

点数ゲームである。

`score_order=desc`、`score_unit=点`、`score_label=最終スコア`、`first_score_label=初回スコア`、`best_score_label=ベストスコア`。

野球の投球ゲームなので、アウト数や勝敗をゲーム内で扱っていても、ランキング値は最終スコアとして送る。

注意点は、勝敗結果だけをランキング値にしないこと。実験場トップでは `ベストスコア` を表示する。

### 13. 子供デモ解けちゃう / `kodomo_demo_tokechau`

点数ゲームである。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。

過去の注意として、結果やシェア文では、誤回答回数と時間切れ数に応じた「ひとこと」を扱う仕様があった。ランキング送信では、ひとことや内訳ではなく最終スコアを送る。

また、過去レビューで、リプレイ中に古い送信結果が次のゲームへ影響する問題が指摘されていた。再プレイ時は古い非同期送信結果が新しい結果画面を書き換えないようにする。

### 14. 目押しを制す / `meoshi_wo_seisu_normal` / `meoshi_wo_seisu_hard`

難易度別ゲームである。

実験場トップでは1枚のカードにまとめる。代表ランキングは高難易度の `meoshi_wo_seisu_hard` を使う。詳細ページではノーマルとハードをタブで分ける。

`score_order=asc`、`score_unit=ゲーム`、`score_scale=1`、`score_decimals=0`。少ないゲーム数ほど上位になる。

親slugの `meoshi_wo_seisu` は詳細ページのまとまりとして使う。スコア保存用の `game_slug` として親slugを使わない。

### 15. マロン飛行 / `maron_hikou`

到達スコアを競うゲームである。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高到達` を表示する。

このゲームは、8桁〜9桁級の大きな整数スコアを扱う。`100040000` や `310312000` のような値は異常値ではない。

注意点は次である。

- 大きな整数スコアを、波数だけに丸めない。
- `31点`、`31波`、`1000点` のように短く変換して送らない。
- `score_scale=1` のまま扱う。
- 秒系のように `100` や `1000` で割らない。
- 表示では `310,312,000点` のように桁区切りしてよい。
- 到達波数を補助表示する場合でも、ランキング順位は大きな整数スコアで決める。
- `score / 10000000` のような計算は表示補助であり、保存スコアを波数に置き換える処理ではない。
- リタイアもプレイ回数として計測する話があったため、リタイア時の送信仕様をゲーム本体側で確認する。
- 過去に、5波以降や40,000以降の記録が登録されない疑いが出ていた。スコア上限、丸め、RPC返答の扱いを必ず確認する。

将来スコア式を変えて21億点を超える可能性がある場合は、先にSupabase側の `score` 型を確認する。

### 16. 取ればいいのよ / `toreba_iinoyo`

点数ゲームである。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高スコア` を出す。

反射ゲームであるため、タイミングや受け取り成功数を内部で扱うが、ランキング値は最終スコアで統一する。棒の本数や成功回数だけを送らない。

### 17. 仕分けざる / `shiwakezaru`

点数ゲームである。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。

過去の最新版では、Supabase返答の `accepted` を確認する、保存済みの名前がある場合は通常クリア時に自動送信する、pointercancel誤判定を防ぐ、という注意があった。

ランキング制作時は、送信が成功したように見えても、RPCの返答で `accepted` を確認する。ゲーム画面のタップ制限や結果画面の入力欄が、送信ボタンや表示を邪魔しないようにする。

### 18. 絵文字拾い / `emojihiroi`

タイムアタックゲームである。

`score_order=asc`、`score_unit=秒`、`score_scale=100`、`score_decimals=2`。実験場トップでは `ベストタイム` を出す。

過去の仕様では、クリア時に `submit_score` を呼び、リタイアでは送信しない扱いだった。リタイアも送る仕様へ変えるなら、別途ゲーム仕様を変更してから行う。

注意点は、タイムを100倍した整数で送ること。秒を小数のまま送らない。

### 19. 間違いみっけ / `machigai_mikke_easy` / `machigai_mikke_hard` / `machigai_mikke_super_hard`

難易度別ゲームである。

実験場トップでは1枚のカードにまとめる。代表ランキングは最高難易度の `machigai_mikke_super_hard` を使う。詳細ページでは、イージー、ハード、超ハードをタブで分ける。

`score_order=asc`、`score_unit=秒`、`score_scale=100`、`score_decimals=2`。小さいタイムほど上位である。

注意点は次である。

- 親slug `machigai_mikke` はスコア保存用の `game_slug` として使わない。
- 3つの難易度slugをSupabaseに登録する。
- 実験場トップは超ハードだけを代表表示する。
- 詳細ページのタブ切り替えでは、RPCに渡すslugを正しく変える。
- 結果シェアはコピー固定の仕様があったため、ゲーム本体側の方針を確認する。
- カウントダウンや名前入力の仕様変更で、ランキング送信を壊さない。

### 20. 熊のFP探し / `kuma_no_fpsagashi`

到達階を競うゲームである。

`score_order=desc`、`score_unit=階`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高到達階` を出す。

注意点は、スコア点ではなく到達階を送ること。`19F` のような表示は、保存値としては `19` にする。表示時に `19階`、必要ならゲーム内文言で `19F` と見せる。

過去にランキング表示がおかしい報告があったため、単位とラベルを必ず確認する。アイテム増殖や食料不足などのゲームバランス修正と、ランキング保存値を混ぜない。

### 21. ジョーバ / `johba`

3D競馬ゲームである。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高スコア` を出す。

このゲームは、ゲーム内でタイムや着順を表示するが、ランキング設定は点数である。タイムランキングではない。

注意点は、低人気加点などを含めた最終スコアを送ること。着順やタイムだけをランキング値にしない。

### 22. 3度一致 / `sandoicchi`

点数ゲームである。

`score_order=desc`、`score_unit=点`、`score_label=サンドスコア`。実験場トップでは `最高スコア` を出す。

過去仕様では、リタイア送信や0未満を0にする扱いがあった。実装時は、ゲーム本体側のスコア確定処理を確認し、失敗・リタイア時の送信値を曖昧にしない。

ステージ別ランキングは不要という方針があった。ランダムステージや追加ステージを入れても、ランキングは1つにまとめる。

### 23. カニジャン / `kanijan`

点数ゲームである。

`score_order=desc`、`score_unit=点`、`score_label=ジャン点`、`first_score_label=初回ジャン点`、`best_score_label=最高ジャン点`。

注意点は、通常の `スコア` ではなく `ジャン点` という表示名を使うこと。ゲーム内の結果画面、実験場トップ、詳細ランキングでラベルをそろえる。

距離、段数、到達地点などを内部で扱っていても、ランキングにはジャン点を送る。

### 24. トレメシ / `toremeshi`

15問ゲームの点数ランキングである。

`score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。実験場トップでは `最高スコア` を出す。

このゲームは、問題文や相談文体、食品データ、プロテインデータなど、ランキング以外の修正が多い。問題文の言い換えやデータ修正の時に、ランキング送信処理を触って壊さない。

1プレイ15問の最終スコアを送る。正解数、惜しい数、不正解数、相談タイプなどを個別にランキング値へ送らない。

## 4. まだ注意が薄いゲーム

過去チャットから明確な個別注意を多く拾えないゲームもある。その場合でも、最低限次だけは守る。

- Supabase最新一覧の `score_order`、`score_unit`、`score_scale`、`score_decimals` を正にする。
- 実験場トップでは `top_ranking_type` を見る。
- 特に指定がなければベストランキングを表示する。
- 詳細ページでは初回とベストを両方出す。
- ゲーム内の補助情報をランキング値と混ぜない。
