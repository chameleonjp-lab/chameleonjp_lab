# 新規ゲーム追加チェックリスト

最終更新: 2026-06-12
対象: 新しいゲームを実験場とランキングに追加する作業

## 1. この文書の役割

新しいゲームを作った時に、Codeberg Pages、Supabase、実験場トップ、詳細ランキングのどこかで漏れが出ないようにするためのチェックリスト。

Claude Codeに新規ゲーム追加を依頼する時は、この文書を読ませる。

## 2. 追加作業の全体順

新しいゲームを公開する時は、次の順で進める。

1. ゲーム本体 `index.html` を完成させる。
2. Codeberg PagesでゲームURLを公開する。
3. ゲーム側にSupabaseスコア自動送信を入れる。
4. Supabase `public.games` にゲーム情報を登録する。
5. 実験場トップでカードが出ることを確認する。
6. 詳細ランキングで `ranking.html?game=slug` が開くことを確認する。
7. スコア送信後、ランキングに出ることを確認する。
8. iPhone SE級、iPhone 17 Pro、iPhone 11 Pro、iPad Proで表示を確認する。

## 3. ゲーム本体の必須確認

ゲーム本体は、原則として `index.html` 1ファイルで作る。

| 確認 | 内容 |
|---|---|
| `GAME_SLUG` | Supabase `games.game_slug` と完全一致 |
| `CLIENT_VERSION` | 日付入りで更新時に変える |
| 名前入力 | 必須。空白だけ不可 |
| 名前保存 | `localStorage` に保存 |
| 結果画面 | スコア、送信状態、シェア、再プレイ、実験場リンク |
| 自動送信 | ゲーム終了時に `submit_score` を呼ぶ |
| 二重送信防止 | 送信中・送信済みフラグあり |
| スマホ対応 | 横スクロール、ズーム、長押し誤操作を抑える |

## 4. Supabase `games` 登録に必要な情報

新規登録前に、次を決める。

| 項目 | 決める内容 |
|---|---|
| `game_slug` | 英数字とアンダースコア。URL名と揃える |
| `title` | 実験場に出すゲーム名 |
| `game_url` | Codeberg Pagesの公開URL |
| `description` | 1文で分かる説明 |
| `share_text` | 結果シェアや実験場シェアで使う文 |
| `display_order` | 実験場での表示順 |
| `is_active` | 公開するなら `true` |
| `top_ranking_type` | `first` または `best` |
| `score_order` | `desc` または `asc` |
| `score_unit` | `点`、`秒`、`%` など |
| `score_scale` | 内部整数から表示値へ変換する倍率 |
| `score_decimals` | 表示小数桁 |
| `score_label` | 通常表示名 |
| `first_score_label` | 初回ランキング名 |
| `best_score_label` | ベストランキング名 |
| `release_date` | 公開日 |

## 5. スコア設定の決め方

ゲームによって、スコア設定を間違えないようにする。

| 種別 | `score_order` | `score_unit` | `score_scale` | `score_decimals` |
|---|---|---|---:|---:|
| 点数が高いほど良い | `desc` | `点` | 1 | 0 |
| タイムが短いほど良い、小数2桁 | `asc` | `秒` | 100 | 2 |
| タイムが短いほど良い、小数3桁 | `asc` | `秒` | 1000 | 3 |
| 誤差が小さいほど良い | `asc` | `秒` など | 100 | 2 |
| 達成率が高いほど良い | `desc` | `%` | 1 | 0 |

ゲーム側が送る内部整数と、Supabase `games` の `score_scale` は必ず合わせる。

## 6. 実験場トップの確認

Supabase `public.games` に登録した後、実験場トップで次を確認する。

- ゲームカードが表示される。
- `display_order` 通りの位置に出る。
- `description` が正しい。
- 遊ぶボタンが `game_url` に飛ぶ。
- シェアボタンの文面にURLが入る。
- 合計プレイ回数と参加人数が表示される。
- 上位ランキングが表示される。
- 記録0件でも壊れない。

もし表示されない場合は、まず次を見る。

```sql
select game_slug, title, is_active, display_order
from public.games
where game_slug = '対象slug';
```

`is_active` が `false` ならトップには出ない。

## 7. 詳細ランキングの確認

詳細ランキングでは、次を確認する。

- `ranking.html?game=対象slug` で開ける。
- ゲーム名、説明、ゲームで遊ぶボタンが正しい。
- 初回ランキングタブが表示される。
- ベストランキングタブが表示される。
- スコア単位と小数桁が正しい。
- 同率順位が `rank_no` 通りに出る。
- 100件まで表示できる。

## 8. スコア送信の確認

ゲームを1回遊び、終了後に次を確認する。

- 結果画面に `ランキング送信中...` が出る。
- 成功時に `ランキングへ送信しました。` のような文言が出る。
- Supabase側で該当ゲームの記録が増える。
- 実験場トップの合計プレイ回数が増える。
- 詳細ランキングに名前とスコアが出る。
- もう一度遊んでも、1回の結果が二重送信されない。

## 9. 公開前のスマホ確認

最低限、次の端末幅を想定して見る。

| 端末 | 見ること |
|---|---|
| iPhone SE級 | はみ出し、ボタンの押しにくさ |
| iPhone 17 Pro | 標準確認 |
| iPhone 11 Pro | 重さ、古め端末の操作感 |
| iPad Pro | 大きい画面での余白、崩れ |

特に、ゲーム中の操作がブラウザの長押し、ズーム、スクロールに奪われないかを見る。

## 10. Claude Codeへの依頼時に伝えること

新しいゲームを追加するときは、Claude Codeに次を渡す。

```text
このリポジトリの CLAUDE.md と docs/chameleonjp-lab/ を読んでください。
新規ゲームをカメレオンJPの実験場へ追加します。
ゲーム本体は index.html 1ファイルです。
Supabaseランキング連携は必須です。
ゲーム終了時に submit_score で自動送信します。
public.games に登録するSQLも作ってください。
実験場トップと詳細ランキングで表示される前提で確認してください。
```

## 11. やってはいけないこと

- Supabase登録だけして、ゲーム側の自動送信を入れない。
- ゲーム側だけ送信して、`public.games` に登録しない。
- `GAME_SLUG` と `games.game_slug` をずらす。
- `score_order` を逆にする。
- 秒系なのに `score_scale = 1` にする。
- 結果画面に任意のランキング登録ボタンを置く。
- `service_role` キーを使う。
- 固定配列だけに新規ゲームを追加して、Supabase `games` を更新しない。

## 12. 完了条件

新規ゲーム追加は、次がすべて通った時に完了とする。

1. ゲームURLで遊べる。
2. ゲーム終了時に自動送信される。
3. Supabase `game_scores` に記録が入る。
4. 実験場トップにゲームカードが出る。
5. 実験場トップのランキングに出る。
6. 詳細ランキングに出る。
7. シェア文にURLが入る。
8. スマホで横スクロールや誤操作がない。
