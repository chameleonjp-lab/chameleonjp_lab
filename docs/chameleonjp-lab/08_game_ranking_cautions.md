# 全ゲーム個別ランキング制作時の注意事項

最終更新: 2026-06-21
対象: カメレオンJPの各ゲーム / 実験場トップ / 詳細ランキング / Supabaseランキング連携

## 1. この文書の役割

この文書は、過去のチャット履歴で何度も問題になったランキング制作時の注意事項を、全ゲーム共通とゲーム個別に分けて整理するための文書である。

新しいゲームを作る時、既存ゲームのランキングを直す時、実験場トップや詳細ランキングを直す時は、`07_current_games_catalog.md` とあわせてこの文書を読む。

## 2. 最初に守る共通ルール

ランキングは、ゲーム本体、Supabase、実験場トップ、詳細ランキングの4つがそろって初めて完成とする。

どれか1つだけ直しても、次のような不具合が起きる。

- ゲーム側では送信しているのに、実験場に出ない。
- Supabaseには登録したのに、詳細ランキングが開けない。
- トップは出るが、スコア単位が違う。
- タイム系なのに大きい数が上位になる。
- 初回ランキングを出すべきゲームで、ベストランキングを出してしまう。

このため、ランキング制作時は次を必ず確認する。

| 確認対象 | 必須確認 |
|---|---|
| ゲーム本体 | `GAME_SLUG`、自動送信、二重送信防止、名前入力、リタイア時の扱い |
| Supabase `public.games` | `game_slug`、`top_ranking_type`、`score_order`、`score_unit`、`score_scale`、`score_decimals`、各ラベル |
| 実験場トップ | カード表示、上位3件ランキング、代表ランキング、難易度別のまとめ方 |
| 詳細ランキング | 初回・ベストの2タブ、最大100件、難易度別タブ、スコア表示 |

## 3. 絶対に使わないもの

過去に何度も事故の原因になったため、次は使わない。

| 禁止 | 理由 |
|---|---|
| `public.scores` | 正しい保存先は `public.game_scores` |
| 古い `get_game_ranking` | 現行は `get_first_try_ranking` と `get_best_score_ranking` |
| `created_at` 前提の並び替え | 実テーブルにない場合がある。基本はRPCの戻り値に従う |
| `index + 1` の順位表示 | 同率順位が壊れる。RPCの `rank_no` を使う |
| `service_role` キー | 公開HTMLに絶対入れてはいけない |
| 任意の「ランキング登録」ボタン | 終了時の自動送信が共通仕様 |

## 4. スコア送信の共通仕様

各ゲームは、ゲーム終了時に自動で1回だけ `submit_score` を呼ぶ。

```js
await supabase.rpc("submit_score", {
  p_display_name: displayName,
  p_game_slug: GAME_SLUG,
  p_score: finalScore,
  p_client_version: CLIENT_VERSION
});
```

結果画面に「ランキング登録」ボタンを置いて、ユーザーが押した時だけ送信する作りにはしない。

送信中・送信済みフラグを必ず持つ。

```text
scoreSubmitStarted
scoreSubmitFinished
```

通信に失敗しても、ゲーム結果画面を消してはいけない。結果画面に「ランキング送信に失敗しました。通信状態を確認してください。」のような文言を出す。

## 5. 名前入力の注意

プレイヤー名は、初回プレイ前に必須入力にする。

- 空白だけの名前は不可。
- 前後の空白は削る。
- 長すぎる名前はランキング表示を壊すため短くする。
- `localStorage` に保存し、次回以降は入力補助に使う。
- 保存キーはゲームごとに分ける。

例:

```js
const NAME_STORAGE_KEY = `chameleonjp_${GAME_SLUG}_player_name`;
```

## 6. 実験場トップのランキング表示ルール

実験場トップのランキングは、特に指定がなければベストランキングを表示する。

| 条件 | 実験場トップで表示するもの | RPC | 表示に使う値 |
|---|---|---|---|
| `top_ranking_type = best` | ベストランキング | `get_best_score_ranking` | `best_score` |
| `top_ranking_type = first` | 初回ランキング | `get_first_try_ranking` | `first_score` |
| 未設定 | ベストランキング | `get_best_score_ranking` | `best_score` |

点数ゲームでは、ベストは最高スコアを意味する。タイム、誤差、ゲーム数のように小さいほど良いゲームでは、ベストは最短・最小記録を意味する。

そのため、`score_order` を必ず確認する。

| `score_order` | 意味 | 例 |
|---|---|---|
| `desc` | 大きいほど良い | 点、階、到達スコア |
| `asc` | 小さいほど良い | 秒、誤差、ゲーム数 |

## 7. 詳細ランキングの共通仕様

詳細ランキングは、1ゲームごとに次の2つを出す。

| タブ | RPC | 表示する値 |
|---|---|---|
| 初回ランキング | `get_first_try_ranking` | `first_score` |
| ベストランキング | `get_best_score_ranking` | `best_score` |

取得件数は最大100件を基本にする。

```js
const DETAIL_LIMIT = 100;
```

表示する順位は `rank_no` をそのまま使う。同点や同タイムでは、`1位, 1位, 3位` のように表示される。

## 8. スコア表示の注意

Supabaseには整数で保存する。表示時は `score_scale` と `score_decimals` を使って変換する。

| 種類 | 保存する内部スコア | 表示設定 |
|---|---:|---|
| 点数 | `12345` | `score_scale=1`, `score_decimals=0`, `score_unit=点` |
| 秒・小数2桁 | `3415` | `score_scale=100`, `score_decimals=2`, `score_unit=秒` |
| 秒・小数3桁 | `1234` | `score_scale=1000`, `score_decimals=3`, `score_unit=秒` |
| 階数 | `19` | `score_scale=1`, `score_decimals=0`, `score_unit=階` |
| ゲーム数 | `7` | `score_scale=1`, `score_decimals=0`, `score_unit=ゲーム` |
| マロン飛行の到達スコア | `100040000` や `310312000` のような8〜9桁整数 | `score_scale=1`, `score_decimals=0`, `score_unit=点` |

秒系ゲームで `score_scale=1` にすると、表示が壊れる。タイム系や誤差系では特に確認する。

マロン飛行のように大きな整数スコアを扱うゲームでは、桁数を理由に波数だけへ丸めたり、表示用に割った値を送ったりしない。保存する値とランキングに使う値は、ゲーム本体が計算した大きな整数スコアそのものにする。

## 9. リタイア・失敗・マイナススコアの注意

過去のやり取りでは、リタイアや失敗もランキング送信対象にするゲームがある。

特に1ステージ制や到達度を競うゲームでは、失敗・リタイアにも記録価値がある。ゲーム仕様で送ると決めた場合は、リタイア時も `submit_score` を使って自動送信する。

注意点は次である。

- リタイア時も送るゲームでは、結果画面を出してから送信する。
- 送るスコアはゲーム仕様で決める。0、到達階、到達波数、失敗タイムなどを混ぜない。
- マイナススコアを許容するゲームでは、勝手に0へ丸めない。
- リタイア後に非同期処理が続いて、後から別スコアが送られないようにする。

## 10. 難易度別ランキングの注意

難易度別ランキングは、詳細ページ内でのみ分ける。

実験場トップでは、難易度ごとのカードを複数出さない。1ゲームとして1枚のカードにまとめ、難易度の高い方のランキングを代表として出す。

| ゲーム | 実験場トップのカード | 実験場トップの代表ランキング | 詳細ページ |
|---|---|---|---|
| 目押しを制す | `meoshi_wo_seisu` | `meoshi_wo_seisu_hard` | ノーマル / ハード |
| 間違いみっけ | `machigai_mikke` | `machigai_mikke_super_hard` | イージー / ハード / 超ハード |

親slugである `meoshi_wo_seisu` や `machigai_mikke` は、詳細ページを開くためのまとまりとして使う。実際にスコアを保存する `game_slug` は、難易度ごとのslugにする。

## 11. ゲーム個別の注意事項

### 虎に優しく

- 点数ゲーム。
- 実験場トップはベストランキング。
- `score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。
- 見出しは `最高スコア`。

### 暇つぶし

- 点数ゲーム。
- 実験場トップはベストランキング。
- `score_order=desc`、`score_unit=点`。

### イロアテ

- タイムゲーム。
- 小さいほど良い。
- `score_order=asc`、`score_unit=秒`、`score_scale=100`、`score_decimals=2`。
- 実験場トップの見出しは `ベストタイム`。
- 秒をそのまま整数で送らない。100倍した整数を送る。

### 夢を見たんだけどさ

- 点数ゲーム。
- 実験場トップはベストランキング。
- `score_order=desc`、`score_unit=点`。

### 水滴キャッチ

- 実験場トップでは例外的に初回ランキングを表示する。
- `top_ranking_type=first`。
- 実験場トップの見出しは `初回スコア`。
- 詳細ページでは初回と最高スコアの両方を出す。

### 上手に描けるかな？

- 達成度・点数系。
- `score_unit=pt`。
- 実験場トップはベストランキング。
- 見出しは `最高スコア`。

### 充電ｶﾞｯ

- 点数ゲーム。
- 実験場トップはベストランキング。
- `score_order=desc`、`score_unit=点`。

### あなたの1秒って

- 誤差が小さいほど良いゲーム。
- `game_slug` は `anatano_1byou`。
- 過去に `anatano_1byo` という誤slugで表示が壊れたことがあるため、必ず `anatano_1byou` に統一する。
- `score_order=asc`、`score_unit=秒`、`score_scale=100`、`score_decimals=2`。
- 実験場トップの見出しは `ベスト誤差`。

### ベク取る

- クリアタイムを競うゲーム。
- ゲーム終了時に自動送信する。
- `score_order=asc`、`score_unit=秒`、`score_scale=1000`、`score_decimals=3`。
- 実験場トップの見出しは `ベストタイム`。
- 結果画面に任意のランキング登録ボタンを置かない。

### 尊厳を賭けようか

- 点数ゲーム。
- 勝利、敗北、引き分け、リタイアの結果画面を出す。
- 決着後は操作受付を止め、最後の状態を表示してから結果へ進む。
- リタイアを送る仕様にする場合は、他ゲームと同じく自動送信し、二重送信を防ぐ。
- `score_order=desc`、`score_unit=点`。

### ヒトを許すな！

- 点数ゲーム。
- ランキング表示で、スコアだけでなくクリア波数や到達波数の意味が必要になる場合がある。
- 実験場や詳細ランキングの表示名を単純な `スコア` だけにすると情報が足りない可能性がある。
- `score_order=desc`、`score_unit=点`。

### 負けたらお前のせいだから

- 点数ゲーム。
- 実験場トップはベストランキング。
- 見出しは `ベストスコア`。
- `score_label=最終スコア`。

### 子供デモ解けちゃう

- 点数ゲーム。
- 実験場トップはベストランキング。
- `score_order=desc`、`score_unit=点`。

### 目押しを制す

- 難易度別ゲーム。
- Supabaseの実スコア保存slugは `meoshi_wo_seisu_normal` と `meoshi_wo_seisu_hard`。
- 実験場トップでは1枚のカードにまとめる。
- 実験場トップで出す代表ランキングはハード。
- `score_order=asc`、`score_unit=ゲーム`。
- 小さいゲーム数ほど良い。
- 詳細ページでノーマルとハードを分ける。

### マロン飛行

- 到達スコアを競うゲーム。
- `game_slug=maron_hikou`。
- 実験場トップはベストランキング。
- 見出しは `最高到達`。
- `score_order=desc`、`score_unit=点`、`score_scale=1`、`score_decimals=0`。
- マロン飛行のランキング値は、8桁〜9桁級の大きな整数スコアになる前提で扱う。
- 例として、`100040000`、`310312000` のような値は異常値ではない。これを `1000点`、`31点`、`31波` のように短く変換して送ってはいけない。
- スコアは内部整数をそのまま `submit_score` の `p_score` に送る。
- 表示では桁区切りを使ってよい。例: `310,312,000点`。
- `score_scale` は `1` のままにする。`100` や `1000` にして秒系のように割ってはいけない。
- 到達波数やクリア波数を補助表示する場合でも、ランキング順位を決める値は大きな整数スコアを使う。
- 30波突破などの進行表示で `score / 10000000` のような計算を使う場合があるが、それは表示用の補助であり、保存スコアを波数に置き換えるための処理ではない。
- Supabaseの `score` が32bit整数の場合、現在想定の数億点台は入るが、将来スコア式を変えて21億点を超える可能性があるなら、先にDBの型を確認する。

### 取ればいいのよ

- 点数ゲーム。
- 実験場トップはベストランキング。
- `score_order=desc`、`score_unit=点`。

### 仕分けざる

- 点数ゲーム。
- 実験場トップはベストランキング。
- `score_order=desc`、`score_unit=点`。

### 絵文字拾い

- タイムアタックゲーム。
- 小さいほど良い。
- `score_order=asc`、`score_unit=秒`、`score_scale=100`、`score_decimals=2`。
- 見出しは `ベストタイム`。

### 間違いみっけ

- 難易度別ゲーム。
- Supabaseの実スコア保存slugは `machigai_mikke_easy`、`machigai_mikke_hard`、`machigai_mikke_super_hard`。
- 実験場トップでは1枚のカードにまとめる。
- 実験場トップで出す代表ランキングは超ハード。
- `score_order=asc`、`score_unit=秒`、`score_scale=100`、`score_decimals=2`。
- 詳細ページでイージー、ハード、超ハードを分ける。
- 親slug `machigai_mikke` をスコア保存用 `game_slug` として使わない。

### 熊のFP探し

- 到達階を競うゲーム。
- `game_slug=kuma_no_fpsagashi`。
- `score_order=desc`、`score_unit=階`、`score_scale=1`、`score_decimals=0`。
- 実験場トップの見出しは `最高到達階`。
- 過去にランキング表示がおかしいという報告があったため、単位とラベルを必ず確認する。
- 到達階を送る。スコア点と混ぜない。

### ジョーバ

- 3D競馬ゲーム。
- `game_slug=johba`。
- 点数ランキング。
- `score_order=desc`、`score_unit=点`。
- タイム表示がゲーム内にあっても、ランキング設定は点数である点に注意する。

### 3度一致

- `game_slug=sandoicchi`。
- 点数ゲーム。
- `score_label=サンドスコア`。
- `score_order=desc`、`score_unit=点`。
- リタイアがある場合は、仕様に従って自動送信する。

### カニジャン

- `game_slug=kanijan`。
- 点数ゲーム。
- 実験場トップの見出しは `最高ジャン点`。
- `score_order=desc`、`score_unit=点`。
- ゲーム内の表示名とSupabaseのラベルを合わせる。

### トレメシ

- `game_slug=toremeshi`。
- 15問ゲームの点数ランキング。
- `score_order=desc`、`score_unit=点`。
- 実験場トップはベストランキング。
- 問題文や相談形式の修正と、ランキングロジックを混ぜて壊さない。

## 12. 新規ゲーム追加時の確認表

新しいゲームを追加する時は、作業前に次を決める。

| 項目 | 決める内容 |
|---|---|
| `game_slug` | ゲーム本体、Supabase、実験場、詳細ランキングで完全一致させる |
| `title` | 実験場カードと詳細ページに出す名前 |
| `game_url` | Codeberg Pagesの公開URL |
| `top_ranking_type` | 実験場トップで初回を出すか、ベストを出すか |
| `score_order` | 大きいほど良いか、小さいほど良いか |
| `score_unit` | 点、秒、階、ゲームなど |
| `score_scale` | 内部整数から表示値へ変換する倍率 |
| `score_decimals` | 表示小数桁 |
| `score_label` | 通常スコア表示名 |
| `first_score_label` | 初回ランキング見出し |
| `best_score_label` | ベストランキング見出し |
| `release_date` | 公開日 |
| `CLIENT_VERSION` | ゲーム本体側の版名 |

## 13. 最終確認チェック

ランキング制作後は、最低限次を確認する。

- 名前未入力では開始できない。
- 終了時に自動送信される。
- 同じ結果が二重送信されない。
- Supabase `public.game_scores` に記録が入る。
- 実験場トップにカードが出る。
- 実験場トップで意図したランキングが3件まで出る。
- 詳細ランキングで初回とベストが出る。
- 難易度別ゲームは詳細ページ内だけで分かれる。
- スコア単位と小数桁が正しい。
- 同率順位が `rank_no` 通りに出る。
- ランキング0件や通信失敗でも画面が壊れない。
- シェア文にゲームURLが入る。
- iPhone SE級の幅で横スクロールが出ない。
